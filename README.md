# Курак: сайт агентства

Next.js 16 (App Router) + TypeScript + CSS Modules + Zustand. Главная и страница команды по документу «Сайт Курак — концепция».

## Идея

Курак по-кыргызски значит лоскутное шитьё. Каждое из восьми направлений агентства — свой «лоскут»: свой цвет и узор, одинаковые по всему сайту (меню, кейсы, руководители, подборка). Посетитель отмечает услуги, и в шапке из них сшивается его собственный курак. Подборка сохраняется на устройстве и подставляется в заявку.

## Запуск

```bash
npm install
npm run dev        # http://localhost:3210
npm run build && npm start
```

### Варианты 10–12: один кыргызский образ на весь сайт

Сделаны по методике, по которой собирали adamtech.kg («Түндүк») и dastanbek.com («Бүркүтчү»): один сквозной образ на стыке кыргызской культуры и того, чем занимается агентство; главный объект во весь экран, огромный заголовок, сюжет на прокрутке со счётчиком; каждая анимация что-то значит; у главного объекта три стиля и у контактов 2–3 варианта с переключателем (выбор запоминается на устройстве, лишнее потом уберём). Главный объект на Canvas, прокрутка на GSAP ScrollTrigger и Lenis; при «уменьшить движение» показывается итоговая картина, без JS статичная SVG-версия.

Факты о культуре проверены по кыргызским источникам (кыргызская Википедия со ссылками на «Кыргызстан. Улуттук энциклопедия» и «Кыргыз сүрөт искусствосу», el-sozduk.kg, 24.kg, kaktus.media); не подтвердившееся на сайт не попало и перечислено в комментарии в начале `src/content/v10.ts`, `v11.ts`, `v12.ts`. Например, говорят «чырмалган чий», а не «ороо чий»; «отоо» — казахское слово, по-кыргызски лунка «үй»; «узун кулак» по-кыргызски означает человека, а не молву.

## Портфолио в PDF

Демо-портфолио (12 страниц 16:9, русский и кыргызский) собирается из страницы `/portfolio` и `/portfolio/kg` (`src/app/portfolio`, `src/components/portfolio`) теми же данными, что и сайт. Пересобрать при запущенном `npm run dev`: `npm run build:portfolio` → `public/portfolio/kurak-portfolio.pdf` и `kurak-portfolio-ky.pdf`. Ссылки «Скачать портфолио» во всех вариантах ведут на эти файлы (`SITE.portfolioPdf`, `portfolioHref(lang)`). Пришлёт агентство своё портфолио — просто замените файлы, ссылки менять не нужно. Образцы в демо-портфолио обведены пунктиром, на каждой странице сноска «демо-версия».

## Демо на GitHub Pages

https://seitek2002.github.io/kurak-site/

```bash
npm run deploy:pages              # собрать статикой и запушить в ветку gh-pages
node scripts/deploy-pages.mjs --no-push   # только собрать в out/
```

Скрипт собирает сайт с `GITHUB_PAGES=true` (статический экспорт, `basePath: /kurak-site`), кладёт `.nojekyll` и форс-пушит `out/` в `gh-pages`. Pages раздаёт ветку `gh-pages`, папка `/`.

На Pages нет сервера: обработчик заявки `src/app/api/lead/route.api.ts` в статическую сборку не входит, и форма пишет, что это демо и заявка не отправлена. Для боевого сайта нужен хостинг с сервером (Vercel или свой Node) либо внешний приёмник заявок в `NEXT_PUBLIC_LEAD_ENDPOINT`.

## Настройки

Скопируйте `.env.example` в `.env.local` и заполните:

- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — заявки уходят в Telegram-бота. Без них форма честно отвечает «не подключена» (503) и не делает вид, что заявка ушла.
- `NEXT_PUBLIC_META_PIXEL_ID`, `NEXT_PUBLIC_GA_ID` — пиксели ретаргетинга (по концепции ставим с первого дня). Пусто — скрипты не грузятся. Событие `Lead` / `generate_lead` отправляется после успешной заявки.
- `NEXT_PUBLIC_SITE_URL` — боевой адрес для sitemap, canonical и Open Graph.

## Фото и логотипы клиентов

Во всех вариантах места под фото (портреты руководителей, фото проектов в кейсах, авторы отзывов) и логотипы клиентов — плейсхолдеры `<PhotoSlot>` (`src/components/brand/PhotoSlot.tsx`): пунктирная рамка, силуэт и подпись «Фото: Оксана», «Фото проекта», «Логотип клиента», в материале каждого варианта. Пришло фото — положите файл в `public/photos/` (например `public/photos/team/oksana.jpg`) и впишите путь без ведущего слеша в `src/content/photos.ts` (`TEAM_PHOTOS.oksana = "photos/team/oksana.jpg"`): плейсхолдер сменится фотографией во всех вариантах сразу. Логотипы клиентов вписываются целиком (`object-fit: contain`), публикуем только с разрешения клиента. В варианте 8 команда нарисована в 2D по концепции (как у Додо), фото там не нужны.
